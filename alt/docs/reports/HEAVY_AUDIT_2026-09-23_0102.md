## RED-1: inside-origin `ray_aabb` reports the ray far bound instead of the computed AABB exit

Affected path: `alt/src/native/littcore/litt_math.h`.

Evidence: canonical `ray_aabb` computes slab `tmin/tmax` and then selects `float t = tmin > r.t_min ? tmin : r.t_max;`. For AABB `[-1,1]^3`, origin `(0,0,0)`, direction `+X`, ray interval `[0,10]`, the computed exit is `tmax=1`, but the fallback returns `r.t_max=10`, producing a reported hit outside the box. Existing gated coverage starts outside the AABB and does not exercise this branch. The support contract promotes C++17 math and the packaged C++ SDK, so this is live supported code.

Required boundary: add a gated regression first, then make only the fallback select computed `tmax`; preserve unrelated zero-direction and boundary policy. Validate outside-origin entry, inside-origin exit, clipped inside-origin miss, and parallel miss.

Regression risk: low for a surgical selection fix; higher if slab logic is refactored, which is not warranted.

Merge readiness: blocked until the regression demonstrably fails before the fix, passes after it, targeted math/SDK gates pass, and full Stabilization passes on the repair and exact merged main.

Current tests prove presence with `{}` but do not prove meaningful configuration is applied or rejected. The promoted C bridge covers entity/component/transform use, while the repository truthfulness constraint forbids successful no-ops for unavailable behavior. No per-type configuration state exists.

Treat null, empty string, and strict empty object as no/default configuration; reject meaningful objects, malformed JSON, arrays/scalars, and other unsupported configuration before mutation; keep Transform data on its dedicated API; document the limitation.

Regression risk: medium because ignored-but-successful inputs become explicit failures, which is the contract-correct behavior.

Merge readiness: requires fail-closed tests, ABI preservation, Windows/Linux/sanitizer bridge coverage, and full exact-main Stabilization.
