## RED-1: inside-origin ray/AABB returns the ray far bound instead of the box exit

Affected path: `alt/src/native/littcore/litt_math.h`.

Current implementation computes slab entry and exit as `tmin` and `tmax`, then selects:

```cpp
float t = tmin > r.t_min ? tmin : r.t_max;
```

For an AABB `[-1,1]^3`, origin `(0,0,0)`, direction `+X`, and ray interval `[0,10]`, the slab exit is `tmax == 1`. Because entry is before `r.t_min`, current code selects `r.t_max == 10`, reporting a hit outside the box. A separate minimal reproduction using the exact selection logic produced the same failure. Existing gated coverage checks an outside-origin entry and does not exercise the inside-origin branch.

This is canonical supported math and ships in the packaged C++ SDK, so the defect is live.

The existing branch `repair/ray-aabb-inside-origin-20260923` is not a finished repair. It is one commit ahead of main and adds only `alt/src/native/littcore/litt_ray_aabb_regression_tests.cpp`. It does not modify `litt_math.h` and the new test source is not wired into the current build or Stabilization workflow. The test cases are useful as a test-first seed, but the branch is not merge-ready and must not be described as a fix.

Required boundary: add the inside-origin cases to a currently gated contract, preferably `alt/src/native/littcore/litt_engine_tests.cpp`, or explicitly wire a dedicated target into all relevant gates. Confirm fail-before. Then change only the fallback selection from the ray far bound to computed slab exit `tmax`. Preserve unrelated boundary and zero-direction policy.

Required cases: outside entry, inside exit, inside exit beyond ray `t_max` as miss, and axis-parallel slab miss.

Current `litt_world_add_component` executes `(void)config_json`, sets only the component-presence bitmap, and returns success. No per-component Mesh/Physics/Light/Camera/Script/Audio/UI configuration storage exists. The current test passes `"{}"` and checks only component presence.

The authoritative runtime contract promotes the versioned C bridge for entity/component/transform use. Repository issue #53 also requires unavailable operations to fail explicitly and forbids successful no-ops. Therefore a meaningful configuration payload cannot truthfully return success while being ignored.

Do not invent component schemas. The validated repair boundary is presence-only behavior with fail-closed configuration semantics: default/no configuration may succeed, while meaningful or malformed configuration must fail before mutating component presence. Transform data remains on its dedicated setter/getter API.

The existing branch `audit-c-bridge-components-20260922` must not be merged or cherry-picked. Its single commit changes only `alt/src/native/litt_c.cpp` but is +26/-305 lines. It deletes unrelated transform, rendering, logging, scripting, and version/ABI implementation while attempting a narrow component repair. The branch also leaves `litt_c_tests.cpp` unchanged. This exactly matches the previously reported blocker and is independently confirmed unsafe.
