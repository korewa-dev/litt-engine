## Repair 1 - Fix inside-origin ray/AABB intersection

Severity: RED

Priority: 1

Affected paths:

- `alt/src/native/littcore/litt_math.h`
- preferably `alt/src/native/littcore/litt_engine_tests.cpp` for the regression

### Why this repair is valid

Current `ray_aabb` computes slab `tmin/tmax` but selects:

```cpp
float t = tmin > r.t_min ? tmin : r.t_max;
```

When the ray starts inside the box, entry is behind the ray minimum and the correct forward intersection is computed `tmax`. Current code instead returns the ray's configured far bound.

Validated example: box `[-1,1]^3`, origin `(0,0,0)`, direction `+X`, interval `[0,10]`. Correct exit is `t=1`; current code reports `t=10`.

### Test first

Put the regression in an already gated test surface, preferably `litt_engine_tests.cpp`, because it is executed by Linux compiler-matrix, Windows native tests, and ASan/UBSan engine contract coverage.

Required cases:

1. outside-origin entry remains correct;
2. inside-origin ray returns computed exit;
3. inside-origin exit beyond ray `t_max` reports no hit;
4. axis-parallel ray outside a slab reports no hit.

Confirm the inside-origin case fails before implementation.

The branch `repair/ray-aabb-inside-origin-20260923` contains a useful four-case test source, but it is not a completed repair. It does not change `litt_math.h` and the new test source is not currently wired into the build or CI. Port the cases into a gated test or explicitly wire the standalone test. Do not merge it as though the bug were fixed.

### Implement

Make the smallest possible code change:

```cpp
float t = tmin > r.t_min ? tmin : tmax;
```

Then keep the existing interval rejection:

```cpp
if (t < r.t_min || t > r.t_max) return {};
```

Do not refactor slab traversal, zero-direction handling, normals, or boundary policy in this repair.

### Validate

At minimum run the currently gated equivalents of:

```sh
make engine-contract-test
make release-hardening-test
make -C alt/src/native cpp-sdk-test
```

Require full Stabilization after the patch and again on exact merged main.

Regression risk: low if surgical.

Merge ready only when fail-before/pass-after evidence exists and all targeted plus full gates are green.

## Repair 2 - Make C bridge component configuration fail closed

Severity: ORANGE

Priority: 2

Affected paths:

- `alt/src/native/litt_c.h`
- `alt/src/native/litt_c.cpp`
- `alt/src/native/litt_c_tests.cpp`

### Why this repair is valid

Current `litt_world_add_component` discards `config_json`, sets only a component presence bit, and returns success. There is no per-component configuration state. Existing coverage sends `"{}"` and only checks presence.

The promoted bridge contract includes entity/component/transform use, and the repository truthfulness rule forbids successful no-op behavior for unavailable capability.

### Do not use the broken repair branch

Do not merge or cherry-pick `audit-c-bridge-components-20260922`.

Its single commit modifies `litt_c.cpp` by +26/-305 lines while attempting a narrow component repair. It removes unrelated transform, rendering, logging, scripting, and ABI/version implementation. It also leaves `litt_c_tests.cpp` unchanged.

Start from fresh current main.

### Specify the narrow contract

Do not invent Mesh, Physics, Light, Camera, Script, Audio, or UI schemas.

Preserve component-presence behavior for valid component enum values.

Treat these as default/no configuration and allow them:

- `nullptr`
- empty string
- strict empty JSON object, including harmless whitespace

Reject these before mutating the component bitmap:

- meaningful JSON objects with fields
- malformed JSON
- arrays
- strings
- numbers
- booleans
- null JSON literal
- other unsupported forms

Transform values remain controlled by the dedicated transform setter/getter APIs.

Document the presence-only semantics next to the public declaration in `litt_c.h`.

### Test first

Add bridge tests proving:

- valid component + `nullptr` succeeds;
- valid component + empty string succeeds;
- valid component + empty JSON object succeeds;
- whitespace-only empty object succeeds if parsed as an empty object;
- meaningful object fails and component remains absent;
- malformed JSON fails and component remains absent;
- array/scalar values fail and component remains absent;
- invalid entity and invalid component type still fail;
- existing add/has/remove behavior for presence remains correct;
- transform setters/getters remain correct.

Confirm at least one meaningful-config test fails against current main before implementation.

### Implement

Use the existing strict JSON parser already present in the native dependency graph instead of hand-written string matching.

Keep the diff local. The implementation should validate configuration, then perform the existing bit mutation. Do not disable valid non-transform component presence merely because their typed configuration is not implemented.

### Validate

Run the C bridge contract locally/CI, inspect the diff for unrelated deletions, then use Repair 3's Windows and sanitizer execution.

Require full Stabilization and exact-main Stabilization.

Regression risk: medium because previously accepted-but-ignored meaningful configuration becomes explicit failure. That change is intentional and contract-correct.
